GUÍA DETALLADA: CÓMO SOLUCIONAR EL ERROR DE PERMISOS DE FIRESTORE ("Missing or insufficient permissions")
================================================================================

Este documento ha sido creado para explicar a fondo la causa del error "Missing or insufficient permissions" al intentar crear e interactuar con el documento de perfil persistente en Firestore, así como para proporcionarte todos los pasos para solucionarlo directamente o mediante soluciones alternativas robustas.

--------------------------------------------------------------------------------
1. LA CAUSA RAÍZ DEL PROBLEMA (¿Por qué ocurre este error?)
--------------------------------------------------------------------------------
El error "Missing or insufficient permissions" (Falta de permisos o permisos insuficientes) de Firebase Firestore ocurre cuando el cliente que ejecuta el código web (en Javascript/React) intenta leer, escribir, crear o actualizar un documento en la base de datos de Firestore en la nube, pero el motor de seguridad de Firestore bloquea la operación.

En el contexto específico de esta aplicación, el error ocurría por tres motivos principales:

A) LLAMADO A UNA FUNCIÓN INEXISTENTE EN LAS REGLAS DE SEGURIDAD (Causa Técnica Principal):
   - En tu archivo 'firestore.rules', varias reglas decisivas para 'activities' y 'notifications' hacían uso de la función `getUserRole()`. Por ejemplo:
     - `getUserRole() != 'tecnico'`
     - `getUserRole() == 'supervisor'`
   - Sin embargo, la función `getUserRole()` NO ESTÁBABA DEFINIDA en absoluto en la sección de funciones de 'firestore.rules' (solo existía `hasUserRole()`).
   - Al no existir esta función, cualquier intento de evaluación de reglas por parte del motor de Firebase en la nube fallaba internamente debido a un error de compilación/ejecución de las reglas. Firestore maneja cualquier fallo de validación interno denegando inmediatamente la operación con un error de "Missing or insufficient permissions".

B) RESTRICCIONES DE VALIDACIÓN DE CORREO (TOKEN JWT) EN EL PERFIL:
   - En las reglas para la creación del perfil en `/users/{userId}` se exige estrictamente que el token del usuario contenga un correo verificado y una estructura específica:
     `'email' in request.auth.token`
   - Si el usuario se autentica pero por algún motivo el token devuelto no contiene la propiedad de email validada en los metadatos de Firebase Auth, la regla de creación falla.

C) REGLAS SIN DESPLEGAR O DESFASADAS:
   - Muchas veces se introducen cambios en el archivo 'firestore.rules' de la carpeta del proyecto, pero estos no se han sincronizado con los servidores de Google Firebase en la nube. Hasta que no se ejecuta el despliegue del proyecto Firebase, la nube sigue aplicando las reglas restrictivas de denegación predeterminadas.

--------------------------------------------------------------------------------
2. PASOS PARA SOLUCIONAR EL PROBLEMA DE RAÍZ
--------------------------------------------------------------------------------
¡Buenas noticias! Como tu asistente de IA, ya he tomado la iniciativa para aplicar y desplegar las dos correcciones más importantes en tu entorno:

PASO 1: DEFINICIÓN DE LA FUNCIÓN FALTANTE EN 'firestore.rules' (COMPLETADO)
   - He modificado el archivo 'firestore.rules' para declarar adecuadamente la función `getUserRole()`. El código integrado e implementado es el siguiente:
     ```javascript
     function getUserRole() {
       return isSignedIn() && exists(/databases/$(database)/documents/users/$(request.auth.uid)) ?
              get(/databases/$(database)/documents/users/$(request.auth.uid)).data.role :
              'unauthorized';
     }
     ```
   - Gracias a esto, el motor de reglas ahora compila perfectamente y puede resolver los roles de los usuarios sin errores lógicos.

PASO 2: DESPLIEGUE AUTOMÁTICO DE REGLAS (COMPLETADO)
   - Acabo de realizar el despliegue físico de las reglas corregidas en la base de datos de tu proyecto (`ai-studio-7b0d9466-7bcd-4162-8ef6-9ffc62ce9d88`). Ya están activas en tiempo real.

PASO 3: RECARGAR LA APLICACIÓN / RE-AUTENTICAR (POR HACER POR EL USUARIO):
   - Al cargar el applet en el navegador de AI Studio, a veces los tokens antiguos quedan cacheados. Para asegurarte de que el cambio se aplica correctamente en tu sesión:
     1. Cierra sesión en el aplicativo web (CANTV).
     2. Limpia la caché básica del navegador o abre una pestaña de incógnito.
     3. Vuelve a iniciar sesión mediante el método de autenticación configurado (Google Login). Esto forzará la generación de un nuevo token JWT y la creación limpia de tu registro de perfil en la base de datos Firestore.

3. SOLUCIONES ALTERNATIVAS (En caso de que persistan trabas o bloqueos recurrentes)
--------------------------------------------------------------------------------
Si en algún momento el error vuelve a aparecer con cuentas específicas de usuarios del personal, puedes optar por las siguientes alternativas de mitigación:

ALTERNATIVA A: REGLAS PERMISIVAS TEMPORALES PARA EL Perfil del Usuario
   - Si por alguna razón la validación estricta de `'email' in request.auth.token` o de atributos adicionales en `isValidUserProfile` bloquea a ciertos usuarios en desarrollo, puedes suavizar la regla de creación/actualización en 'firestore.rules'.
   - Modificación sugerida para el bloque de `/users/{userId}` en `firestore.rules`:
     ```javascript
     match /users/{userId} {
       allow get, create, update: if isSignedIn() && request.auth.uid == userId;
       allow list, delete: if isAdmin();
     }
     ```
   - Esto permite que cada usuario autenticado tenga control total para leer o registrar su propio perfil de forma directa, eliminando validaciones excesivas de campos complejos durante etapas primarias de testing. Si la modificas, recuerda desplegarla usando la herramienta de despliegue.

ALTERNATIVA B: PERMITIR CAPA AUXILIAR EN MEMORIA (YA SOPORTADO EN CÓDIGO)
   - El código de `src/App.tsx` en la línea 575 está diseñado para ser sumamente tolerante a fallas.
   - Si la base de datos rechaza la creación/actualización por permisos en la nube, el sistema captura el error (`catch (createErr)`) y continúa estableciendo el perfil en memoria para la sesión activa (`setUserProfile(profileToSet)`).
   - Esto significa que, aunque veas el aviso en la consola de depuración, el usuario podrá interactuar en la pestaña activa con normalidad.

ALTERNATIVA C: DESACTIVAR LA CREACIÓN AUTOMÁTICA SI YA EXISTE LA PLANTILLA DE PERSONAL
   - Si el técnico ya se encuentra registrado preventivamente por el supervisor en la colección `technicians` con su correo electrónico correspondiente, se puede modificar el flujo para que use y herede esa especificación directamente en su sesión en lugar de obligar al cliente a registrar un nuevo documento en la colección de `/users`.

ALTERNATIVA D: VERIFICACIÓN DEL PROYECTO FIREBASE DE AI STUDIO
   - Si notas que AI Studio está perdiendo la conexión con tu proyecto, puedes re-vincularlo abriendo los paneles de configuración y seleccionando "Configurar Firebase" nuevamente. Esto re-sincroniza las credenciales lógicas y asegura que el ID del proyecto de tu archivo `firebase-applet-config.json` coincida exactamente con las bases de datos de Google Cloud en producción asignadas a tu contenedor de ejecución.

--------------------------------------------------------------------------------

--------------------------------------------------------------------------------

2. Editamos `firestore.rules` instalando y definiendo el nuevo ayudante.
